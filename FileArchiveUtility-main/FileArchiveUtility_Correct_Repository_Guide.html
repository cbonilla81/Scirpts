01 / What it does

File Archive Utility helps operators evaluate old files and relocate selected content without flattening its folder hierarchy. This documentation is based on the README in Scirpts/main/FileArchiveUtility-main.

🔎

Discover

Scan local folders or accessible UNC paths.

⚙

Filter

Apply age and edition-specific filters.

🛡

Preview

Use Dry Run before modifying data.

📦

Archive

Move files while preserving subfolders.

Important: Live archiving moves files; successfully moved files no longer remain at their original source location. Verify backup, retention, legal hold, and permissions before production use.

03 / Architecture overview

Conceptual diagram, not a claim that the four editions share a single running backend. Each edition is a separate entry point; the hosted application executes filesystem operations under its IIS application-pool identity.

04 / Requirements and permissions

Supported Windows environments

Windows 10/11 or Windows Server 2016, 2019, 2022 and newer. Windows PowerShell 5.1 is recommended for the script. .NET 8 SDK is required to run .NET projects from source.

Published runtime dependencies

Local web package: .NET 8 ASP.NET Core Runtime. Hosted IIS edition: .NET 8 Hosting Bundle and IIS. For hosted builds, use a build machine with the .NET 8 SDK.

Filesystem rights: The operator or service identity needs sufficient read/list rights at source and create/write rights at destination, plus delete rights where moves or cleanup require them. For network shares, check both SMB share and NTFS permissions.

07 / PowerShell GUI

Run the interactive script in STA mode:

powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File ".\Archive-OldFiles-GUI.ps1"
  1. Choose a source folder or enter a UNC path.
  2. Choose an archive destination that is neither the source nor a subfolder of the source.
  3. Set age threshold (default: 365 days).
  4. Leave Dry Run enabled; click Run Archive.
  5. Review the live status and text/CSV report.
  6. Only after validation, disable Dry Run and confirm the live operation.

Optional features include removal of qualifying empty source folders and replacement of destination files when the source file is newer. Overwrite is disabled by default.

08 / Windows Forms desktop edition

Launch from source with the .NET 8 SDK:

dotnet run --project .\FolderArchiveTool\FolderArchiveTool.csproj

Publish and package for Windows x64:

.\build_and_package.ps1

Features include candidate review, per-item move/overwrite prompts, Dry Run, live moves, optional empty folder removal, and folder compression to ZIP. The README states that its current age threshold is 365 days.

09 / Localhost browser console

.\run_web_console.ps1

Open http://localhost:5187. Keep the PowerShell window running; use Ctrl+C to stop it. This edition binds to localhost and must not be exposed by changing its loopback binding. The hosted edition uses the same folder-selection UI and archive service.

Filter and scan

Configure the minimum file age (365 days by default), included and excluded extensions, minimum and maximum size, and excluded path values. A file must be older than the age threshold by both its last-access and last-modified timestamps and must pass the other configured filters. Last-access tracking depends on Windows and filesystem settings.

The scan lists source subfolders recursively. Each folder's eligible file count and size include only files matching the filters; the nested-folder count describes the scanned folder structure. Reparse-point folders are not followed. Files directly under the source root are not included.

Select and archive folders

Select folders rather than individual files. Selecting a parent includes matching files from all its nested folders, and the UI prevents overlapping parent/child selections. The header checkbox selects all top-level folders, covering the whole subfolder tree. A selected folder does not mean move every item: only files that pass the configured filters are archived. Relative paths are preserved at the destination, which is created as needed. Empty source subfolders can optionally be removed after successful moves.

Dry Run is enabled by default. Review its output before disabling Dry Run and confirming a live move. Existing destination files are skipped unless replacement is enabled and the source file is newer. The archive job rechecks filter eligibility before processing files.

Exports and activity

Export folder list downloads all folders from the latest scan with eligible-file counts, eligible sizes, nested-folder counts, and selection state. Export job output downloads the completed job summary and activity log. These are on-demand CSV downloads, not persistent reports. Progress and activity appear in the browser while a job runs. The web consoles do not currently provide folder compression.

To create the Windows x64 package:

.\build_web_console.ps1
# Extract FolderArchiveWebConsole_Package.zip
# Run FolderArchiveWebConsole.exe

For a static UI preview, open web-console-demo.html. It uses sample data only and does not scan or move files. The hosted sign-in and console walkthrough is in hosted-web-console-demo.html.

Deployment checklist

  1. Register a single-tenant application in Microsoft Entra ID and record tenant/client IDs.
  2. Add HTTPS callback URLs /signin-oidc and /signout-callback-oidc for your actual hostname.
  3. Create and securely store a client secret; set Assignment required = Yes in the enterprise application and assign approved users/groups.
  4. Run the hosted build script on the .NET 8 SDK machine.
  5. Install IIS and the .NET 8 Hosting Bundle on Windows Server; configure DNS, HTTPS certificate, and allowed network access.
  6. Deploy the ZIP to a protected directory, create an IIS app pool with No Managed Code, and configure a least-privileged service identity.
  7. Set the three required authentication configuration values and recycle the app pool.
  8. Test allowed and denied sign-ins, Dry Run, permissions boundaries, and disposable live moves.
.\build_hosted_web.ps1
# Output: FolderArchiveWebHosted_Package.zip

Required authentication settings

Authentication__Microsoft__TenantId=YOUR-TENANT-GUID
Authentication__Microsoft__ClientId=YOUR-CLIENT-GUID
Authentication__Microsoft__ClientSecret=YOUR-SECRET-VALUE
Secret handling: Do not commit credentials to GitHub or bundle them in deployment ZIPs. If configured in IIS web.config, restrict its NTFS permissions. Use your organization's approved secret-management approach.
Concurrency: The hosted app allows one active job per server process. Job status is held in memory and is lost on process recycle; the guard is not distributed across multiple IIS instances.

For a static preview, open hosted-web-console-demo.html; its login and file operations are simulated.

11 / Security and trust boundaries

Identity ≠ filesystem permissions

Entra ID authenticates users. The hosted server accesses files as the IIS application-pool identity, not the signed-in user.

Least privilege

Limit the service identity to approved source/archive locations with share and NTFS ACLs. Prefer a managed domain account or gMSA for UNC shares.

Safe operations

Dry Run first, test on disposable data, review collisions, confirm backups, and exclude legal hold or regulated folders.

Web protections

Use HTTPS, Entra app assignments, authenticated pages/APIs, anti-forgery tokens, and regular secret rotation.

12 / Logs, exclusions, and behavior

The PowerShell GUI creates timestamped text and CSV reports under:

C:\ProgramData\FileArchiveUtility\Logs
Archive_YYYYMMDD_HHMMSS.log
Archive_YYYYMMDD_HHMMSS.csv

CSV fields include timestamp, item type, source/destination paths, sizes, status, and details. Statuses include Archived, WhatIf, Skipped, Failed, and Removed.

Default PowerShell GUI exclusions

$script:ExcludedExtensions = @(".tmp", ".lock")
$script:ExcludedFolderNames = @("ActiveProjects", "LegalHold", "DoNotArchive")

Edit these arrays near the top of the PowerShell script to adjust its defaults. The web consoles have configurable age, extension, size, and excluded-path filters; those filters determine the eligible counts and sizes shown in the folder list and the files moved from selected folders. Web-console CSV exports are generated when requested and are not retained as persistent reports. Web consoles do not currently provide folder compression.

13 / Safe hands-on test lab

Create a small source directory with an old and a new test file:

New-Item -ItemType Directory -Force C:\ArchiveTest\Source, C:\ArchiveTest\Destination
New-Item -ItemType File -Force C:\ArchiveTest\Source\OldFile.txt
New-Item -ItemType File -Force C:\ArchiveTest\Source\NewFile.txt
(Get-Item C:\ArchiveTest\Source\OldFile.txt).LastWriteTime = (Get-Date).AddDays(-400)
(Get-Item C:\ArchiveTest\Source\NewFile.txt).LastWriteTime = (Get-Date).AddDays(-30)
Expected PowerShell GUI behavior: At a 365-day threshold, OldFile.txt is eligible and NewFile.txt is not. For web-console testing, account for the additional last-access-time requirement.

14 / Troubleshooting

PowerShell GUI does not open

Run in STA mode using powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File ".\Archive-OldFiles-GUI.ps1".

Access denied or source path missing

Check DNS, share names, source/destination NTFS and SMB permissions, and the actual account executing the utility.

Test-Path "\\FileServer01\Data"
Test-Path "\\ArchiveServer01\Archive\Data"
Files are skipped unexpectedly

Check the age cutoff, excluded extensions/folders, existing destination files, and access permissions. For web consoles, check both last access and last modified dates.

Hosted app HTTP 500.30

Verify the .NET 8 Hosting Bundle, IIS app-pool permissions, tenant/client IDs, secret value, and Windows Application event log.

Hosted sign-in loop / redirect mismatch

Confirm HTTPS hostname, port, /signin-oidc, and /signout-callback-oidc exactly match Entra registration.

Hosted login works, but UNC access fails

The IIS application-pool identity needs network credentials and both share and NTFS permissions. Use an approved domain account or gMSA.

Logs cannot be written

For the PowerShell GUI, check write permissions to C:\ProgramData\FileArchiveUtility\Logs.
